# Data dictionary

One row = one auction lot. Column names are the SQLite names; the Excel header is in brackets.

| Column [Excel] | Type | Description | Origin |
|---|---|---|---|
| `id` | text | Unique key: `source:lot-id-on-that-source`. Not exported to Excel. | built |
| `source` [Site] | text | Site the row was collected from (`christies.com`, `collectorsquare.com`, `sothebys.com`). | built |
| `maison` [Maison de vente] | text | Auction house that held the sale. Differs from `source` for aggregator rows. | source |
| `vente` [Vente] | text | Sale reference: number, location, sale type or title. | source |
| `date_vente` [Date de vente] | date `YYYY-MM-DD` | Sale date (end date for multi-day online sales). | source |
| `lot` [N° de lot] | text | Lot number within the sale. | source |
| `url` [Lien URL] | text | Lot page. For CollectorSquare, the model index page (lots have no page of their own there). | source |
| `marque` [Marque] | text | Brand, normally `Hermès`. | source / title |
| `modele` [Modèle] | text | Model and variants, e.g. `birkin sellier`, `kelly retourne`. CollectorSquare rows use its label, e.g. `Birkin 35 cm`. | source / parsed |
| `taille` [Taille] | text | Size in cm (`25`, `28`, `30`, `35`…). | parsed |
| `couleur` [Couleur] | text | Hermès colour name as written (`etoupe`, `rouge h`, `bleu jean`). CollectorSquare rows show `colour family / parsed colour`. | parsed / source |
| `matiere` [Matière] | text | Leathers or skins found, comma-separated (`togo`, `epsom, swift`, `porosus, crocodile`). | parsed / source |
| `quincaillerie` [Quincaillerie] | text | Hardware finish (`palladium`, `gold`, `brushed gold`, `rose gold`, `permabrass`). | parsed |
| `annee` [Année de fabrication] | integer | Year of manufacture from the title or date stamp. | parsed |
| `etat` [État] | text | Condition: Christie's grade (`Grade 1` = unused … `Grade 3` = visible wear) or the source's label. | parsed / source |
| `vendu` [Vendu] | 0/1 → Non/Oui | 1 = sold, 0 = unsold or withdrawn, empty = unknown. | source |
| `estimation_basse` [Estimation basse] | number | Low estimate, in `devise`. | source |
| `estimation_haute` [Estimation haute] | number | High estimate, in `devise`. | source |
| `prix` [Prix (marteau)] | number | Price when the source does not say it includes fees (CollectorSquare). | source |
| `devise` [Devise] | text | ISO currency of the sale (`USD`, `HKD`, `EUR`, `GBP`, `CHF`). | source |
| `prix_frais_inclus` [Prix frais inclus] | number | Final price including buyer's premium (Christie's price realised, Sotheby's "lot sold"). | source |
| `titre` [Titre du lot] | text | Original lot title, kept so parsed values can be checked. | source |
| `remarques` [Remarques / Autres] | text | Notes: withdrawn, estimate or price on request, EUR conversion and description (CollectorSquare). | source |
| `scraped_at` | datetime | When the row was last collected. SQLite only. | built |

**Origin:** *source* = given as a field by the site; *parsed* = extracted from the title by `src/parse.ts`; *built* = generated by the scraper.

## Reading the prices

- A sold lot has either `prix` or `prix_frais_inclus` filled, depending on the source; check which one before comparing.
- Estimates are always without fees.
- *Sell-through* = `vendu = 1` / all lots with `vendu` not empty.
- *Price vs estimate* = `prix_frais_inclus / estimation_haute`: above 1 means it beat the high estimate.
